为什么有两个通过率

每个断言集都含一条 DELIBERATE-FAIL：一条故意写错、必须失败的断言。它的作用是证明判据引擎真的会判失败——否则一个永远返回 true 的评测器也能报告 100%。

所以表格里的「有效通过率」剔除这条自检用例，代表插件真实表现；「原始」列是含自检用例的数字，也就是直接跑 npm run eval:all 时终端里看到的那个。两个数字都对，口径不同。

若出现非自检的真实失败，会被单独标红并计入「有效通过率」，不并入自检口径。
